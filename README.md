# 上海酒吧推荐 Agent 🍸

> 多维度对比推荐的完整产品 —— 输入「酒 + 时间 + 位置 + 预算」，输出多维对比推荐报告。
> 本地部署（Dify Docker + DeepSeek v4-flash），已发布可现场演示。

## 定位

用户要的不是「附近有酒吧」，而是「**这个时间、这个预算、这个场景，该去哪**」。
把模糊需求拆成可评估的维度，用真实数据做多维度对比 —— 这是评估体系思路的延伸。

## 架构（13 节点 + 实时地图数据）

```
开始（用户输入）
  → 参数提取 LLM（酒/时间/位置/预算/场景/搜索词 → JSON）
  → 位置提取 + 关键词提取（并行，从参数 JSON 拆出纯文本）
  → 清洗节点（Python code：剥离 deepseek think 块 + 空白）
  → 地理编码（高德 API：位置 → 经纬度）
  → 坐标解析 LLM → 清洗
  → 周边酒吧搜索（高德 API：经纬度 + 酒种关键词 → 真实 POI）
  → POI 整理 LLM（真实距离/评分/人均/营业时间 → 候选表）
  → 口碑与时段分析 LLM（性价比/时段适配/步行时间）
  → 多维对比输出 LLM（对比表 + Top3 + 场景建议 + 数据来源声明）
  → Answer
```

**外接数据源（客观真实）**：高德地图 Web 服务 API
- 地理编码 `/v3/geocode/geo`：位置文本 → 经纬度
- 周边搜索 `/v3/place/around`：经纬度 + 酒种关键词 → 真实 POI（distance 距离 / rating 评分 / cost 人均 / opentime2 营业时间 / type）
- key 本地配置，不入库

## 实测（威士忌 + 安福路 + 人均 200 + 约会）

全部为高德实时返回的真实数据：

| 酒吧 | 距离 | 评分 | 人均 | 营业时间 |
|---|---|---|---|---|
| 麦坊 Maltfun 威士忌·雪茄（首选） | 399米/步行5分钟 | 4.6 | 219 | 至 02:30 |
| 崃州吧（次选·预算内） | 869米/11分钟 | 4.6 | 159 | 至 01:00 |
| Something Space Bar（品质优先） | 2461米/31分钟 | 4.8 | 148 | 至 02:00 |
| Helens 海伦司（高性价比） | 2049米/26分钟 | 4.7 | 76 | 至 02:00 |

输出：多维对比表（距离/评分/人均/营业时间/类型/性价比/时段适配）+ Top3 理由 + 场景细分（约会/聚会/小酌）+ 数据来源声明（「实际营业时间/人均以到店为准」）。

## 工程要点（踩坑实录）

- Dify HTTP 节点参数用 `params` 字段（`key: value` 冒号分隔多行），自动 urlencode —— URL 内嵌变量遇换行会报 Invalid URL
- deepseek 输出带 `<think>` 推理块 → code 节点正则剥离后再入 URL
- 中文参数写原文（如 `city: 上海`），不要预编码（会双重编码）
- **数据缺失时 Agent 诚实降级**（接口异常时如实说明，不编造数据）—— 评估体系原则贯穿产品

## 现场演示

本地 Dify（http://localhost）→ 工作室 →「上海酒吧推荐 Agent」→ 预览。
建议问题开箱即用：
- 晚上想喝威士忌，在安福路附近，预算人均200左右，适合约会
- 周五晚上精酿啤酒，静安寺，和哥们几个，性价比高一点
- 下午想找个安静的地方喝葡萄酒，前滩附近

## 已知限制

Dify 1.16.1 Chatflow 多轮 memory 触发后端 KeyError: 'type' bug（任何多轮会话 500），当前为单轮稳定版；现场演示用单轮提问即可。

**关于客观性**：本作品的数据（评分/人均/营业时间/距离）全部来自高德地图真实 API 返回，非人工编造；推荐结论基于参数化规则对比，可复现。
