## 01 回答质量评估 Agent 📊

- **定位**：输入「用户问题+模型回答」→ 4 维评分（准确性/相关性/可信度/完整性 1-5）+ 原文证据 + BadCase 归因 + 优化建议
- **知识资产**：评测项目 rubric（`~/Desktop/llm-eval-project/rubric.md`）产品化
- **实测**（真实 badcase：黑神话 DLC 时效错误）：
  - 准确性 1/5（正确识别"2024-08-20 已发售，回答却说未发售"+原文证据）
  - 归因：知识截止，严重度高——与评测项目人工评分（T04：1/3/2/2）高度一致
- **面试故事**：「我不只做过一次评估，我把它做成了工具」

## 02 模型能力与算力评估 Agent 🧠

- **定位**：输入场景（任务/预算/硬件）→ 模型推荐 + 架构要点 + 显存/量化算力需求 + 能力边界 + 备选方案
- **知识资产**：本地部署实操经验（Qwen3.6 35B / Qwen3.8 27B）+ 显存估算公式 + 量化对比（`model_kb.md`）
- **实测**：「24GB 显卡部署中文办公助手」→ 推荐 Qwen3.8 27B INT4（15-16GB 显存、中文能力≈35B 的 90%+、Ollama 部署建议）
- **面试故事**：「我本地部署过多款模型，把它做成了团队可用的选型工具」

## 03 外部信源验收 Agent 🔍

- **定位**：输入信源描述（URL/字段/更新频率/用途）→ 按验收清单评估：字段完整性 / 内容质量抽检 / 可信度 / 风险点 / 验收结论
- **知识资产**：信源接入 checklist（`source_checklist.md`），方法论源自知识图谱 OCR 管线（字段定义→质量校验→上线验证）
- **实测**：「政府房价数据接口验收」→ ⚠️ 有条件通过（权威性基础好，抽样数据待补充）——不编造数据，缺失项明确标注
- **面试故事**：「信源接入不是『接个 URL 就完事』，是字段/质量/可信度/效果的完整验收——我把它流程化了」

## 04 用户反馈归因 Agent 💬

- **定位**：输入多条用户反馈 → 去重聚类（问题类型/严重度）→ BadCase 归因（维度/严重度/归因类型/优化方向）→ 沉淀新增评估 case 建议
- **实测**（3 条真实反馈）：
  - 聚类：准确性错误（高）/ 理解错误（高）/ 体验问题（中）
  - 归因：知识截止（建议接实时知识库+当前时间判断）/ 地理实体消解失败（建议槽位校验）/ 产品设计问题（建议长度偏好识别）
  - 产出可落地 case：「提问黑神话是否发售+当前日期 2026，验证回答是否体现已发售」
- **面试故事**：「用户反馈不是投诉，是可复用的测试集——我把闭环流程化了」

## 05 上海酒吧推荐 Agent 🍸（完整产品型作品）

**定位**：多维度对比推荐的完整产品——输入「酒 + 时间 + 位置 + 预算」，输出多维对比推荐报告。

**架构（13 节点 + 实时地图数据）**：
```
开始（用户输入）
  → 参数提取 LLM（酒/时间/位置/预算/场景/搜索词 → JSON）
  → 位置提取 + 关键词提取（并行，从参数 JSON 拆出纯文本）
  → 清洗节点（Python code：剥离 deepseek think 块 + 空白）
  → 地理编码（高德 API：位置 → 经纬度）
  → 坐标解析 LLM → 清洗
  → 周边酒吧搜索（高德 API：经纬度 + 酒种关键词 → 真实 POI）
  → POI 整理 LLM（真实距离/评分/人均/营业时间 → 候选表）
  → 口碑与时段分析 LLM（性价比/时段适配/步行时间）
  → 多维对比输出 LLM（对比表 + Top3 + 场景建议 + 数据来源声明）
  → Answer
```

**数据源（生产级）**：高德地图 Web 服务 API 实时搜索（key 本地配置，不入库）：
- 地理编码 `/v3/geocode/geo`：位置文本 → 经纬度
- 周边搜索 `/v3/place/around`：经纬度 + 酒种关键词 → 真实 POI（distance 距离 / rating 评分 / cost 人均 / opentime2 营业时间 / tel / type）
- 知识库 `bar_data_60.csv`（60 家）保留在库中作为候选补充/兜底

**实测**（威士忌+安福路+人均200+约会，全部真实数据）：
- 麦坊 Maltfun 威士忌·雪茄：399 米/步行5分钟，4.6 分，人均 219，营业至 02:30（首选）
- 崃州吧：869 米/11 分钟，4.6 分，人均 159（次选，预算内性价比高）
- Something Space Bar：2461 米/31 分钟，4.8 分，人均 148（品质优先）
- 输出：多维对比表（距离/评分/人均/营业时间/类型/性价比/时段适配）+ Top3 理由 + 场景细分（约会/聚会/小酌）+ 数据来源声明（"实际营业时间/人均以到店为准"）

**工程要点（踩坑实录）**：
- Dify HTTP 节点参数用 `params` 字段（`key: value` 冒号分隔多行），自动 urlencode——URL 内嵌变量遇换行会报 Invalid URL
- deepseek 输出带 `<think>` 推理块 → code 节点正则剥离后再入 URL
- 中文参数写原文（如 `city: 上海`），不要预编码（会双重编码）
- 数据缺失时 Agent 诚实降级（返回 INVALID_PARAMS 时不编数据，给兜底建议）——评估体系原则贯穿产品

**已知限制（诚实记录）**：Dify 1.16.1 Chatflow 多轮 memory 触发后端 KeyError: 'type' bug（任何多轮会话 500），当前为单轮稳定版。

**面试故事**：「用户要的不是'附近有酒吧'，是'这个时间这个预算这个场景该去哪'——参数提取 + 高德真实 POI + 多阶段分析，把多维对比做成了生产级产品。这也是评估体系思路的延伸：好产品=把模糊需求拆成可评估的维度，数据缺了就诚实说，不编。」
