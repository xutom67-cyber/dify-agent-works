## 01 回答质量评估 Agent 📊

- **定位**：输入「用户问题+模型回答」→ 4 维评分（准确性/相关性/可信度/完整性 1-5）+ 原文证据 + BadCase 归因 + 优化建议
- **知识资产**：评测项目 rubric（`~/Desktop/llm-eval-project/rubric.md`）产品化
- **实测**（真实 badcase：黑神话 DLC 时效错误）：
  - 准确性 1/5（正确识别"2024-08-20 已发售，回答却说未发售"+原文证据）
  - 归因：知识截止，严重度高——与评测项目人工评分（T04：1/3/2/2）高度一致
- **面试故事**：「我不只做过一次评估，我把它做成了工具」

## 02 模型能力与算力评估 Agent 🧠

- **定位**：输入场景（任务/预算/硬件）→ 模型推荐 + 架构要点 + 显存/量化算力需求 + 能力边界 + 备选方案
- **知识资产**：本地部署实操经验（Qwen3.6 35B / Qwen3.8 27B）+ 显存估算公式 + 量化对比（`model_kb.md`）
- **实测**：「24GB 显卡部署中文办公助手」→ 推荐 Qwen3.8 27B INT4（15-16GB 显存、中文能力≈35B 的 90%+、Ollama 部署建议）
- **面试故事**：「我本地部署过多款模型，把它做成了团队可用的选型工具」

## 03 外部信源验收 Agent 🔍

- **定位**：输入信源描述（URL/字段/更新频率/用途）→ 按验收清单评估：字段完整性 / 内容质量抽检 / 可信度 / 风险点 / 验收结论
- **知识资产**：信源接入 checklist（`source_checklist.md`），方法论源自知识图谱 OCR 管线（字段定义→质量校验→上线验证）
- **实测**：「政府房价数据接口验收」→ ⚠️ 有条件通过（权威性基础好，抽样数据待补充）——不编造数据，缺失项明确标注
- **面试故事**：「信源接入不是『接个 URL 就完事』，是字段/质量/可信度/效果的完整验收——我把它流程化了」

## 04 用户反馈归因 Agent 💬

- **定位**：输入多条用户反馈 → 去重聚类（问题类型/严重度）→ BadCase 归因（维度/严重度/归因类型/优化方向）→ 沉淀新增评估 case 建议
- **实测**（3 条真实反馈）：
  - 聚类：准确性错误（高）/ 理解错误（高）/ 体验问题（中）
  - 归因：知识截止（建议接实时知识库+当前时间判断）/ 地理实体消解失败（建议槽位校验）/ 产品设计问题（建议长度偏好识别）
  - 产出可落地 case：「提问黑神话是否发售+当前日期 2026，验证回答是否体现已发售」
- **面试故事**：「用户反馈不是投诉，是可复用的测试集——我把闭环流程化了」

## 05 上海酒吧推荐 Agent 🍸（完整产品型作品）

**定位**：多维度对比推荐的完整产品——输入「酒 + 时间 + 位置 + 预算」，输出多维对比推荐报告。

**架构（8 节点 + RAG + HTTP 外部工具）**：
```
开始（用户输入）
  → 参数提取 LLM（酒/时间/位置/预算/场景 → JSON）
  → 酒吧检索（知识库 RAG：60 家上海酒吧数据）
  → 候选整理 LLM（列表 + 距离评估：较近/适中/较远）
  → 评价与活动分析 LLM（平台口碑：优点/缺点 + 近期活动 + 时段适配）
  → 上海实时天气（HTTP 工具节点：Open-Meteo 真实 API 调用，无需 key）
  → 多维对比输出 LLM（对比表 + 决策卡 + 天气/预算/时段建议）
  → Answer
```

**知识库**：`bar_data_60.csv`（60 家公开知名酒吧，覆盖 15 个区域：外滩/新天地/静安寺/安福路/衡山路/前滩/虹桥/古北/徐家汇/五角场/滨江/中山公园/大宁等，标注「公开信息整理，演示用」）

**外部工具**：HTTP 请求节点实时调用 Open-Meteo 获取上海天气，天气维度融入推荐（高温→推荐 Highball/冰饮，雨天→室内酒吧提醒）

**实测**（威士忌+安福路+人均200+约会）：
- 推荐 Bar No.3（首选）/ Precedent（次选）/ UVA（备选），输出「最终决策卡」（优先级表格+匹配关键词+一句话决策）
- 天气维度：「温度略高，喝威士忌建议优先选 Highball 或加冰纯饮，清爽解暑」
- 预算策略：「两人点 2-3 杯+小吃可控制在 350-400 元」+ 避开建议 + 营业时间提醒（诚实标注"出发前电话确认"）
- 回答带知识库引用（可溯源）

**产品化要点**：
- HTTP 工具节点（真实外部信源调用）——回应「架构不能只有 LLM 节点」
- 参数提取节点让口语化输入结构化（"和哥们几个"→场景=朋友聚会）
- 输出带引用（retriever_resource），回答可溯源
- 提示词防 CoT 泄漏

**已知限制（诚实记录）**：Dify 1.16.1 Chatflow 多轮 memory 触发后端 KeyError: 'type' bug（任何多轮会话 500），当前为单轮稳定版；多轮可通过 API 侧管理 conversation 规避。

**面试故事**：「用户要的不是'附近有酒吧'，是'这个时间这个预算这个场景该去哪'——参数提取 + RAG + 实时天气工具 + 多阶段分析，把多维对比做成了完整产品。这也是评估体系思路的延伸：好产品=把模糊需求拆成可评估的维度。」
